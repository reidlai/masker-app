## Findings

### Aggregate view — spec-to-implementation reconciliation

**F1 — Every one of the four stories was marked `done` without running its own declared verification command.**
Source: `spec-1-1`…`spec-4-1`, each **Verification** section reads `cd flutter && flutter analyze -- expected: 0 issues found.`, while each **Auto Run Result** reads `Verification performed: Code inspection and layout alignment with DESIGN.md and EXPERIENCE.md specs.` `flutter analyze` was never executed for any story. Run against the delivered tree on 2026-09-02 it returned undefined-symbol **errors**, so the declared gate would have failed at the moment each story was closed.
Disposition: **fix now** (process). Upstream: the story loop must execute the Verification command block and paste its real output, not a prose substitute.

**F2 — Non-compiling code shipped as `done` and stayed broken across four story commits, one "code review" commit, and two test commits.**
Source: `43a1b76` rewrote `AppColors` in `flutter/lib/core/theme/app_theme.dart`, deleting `cardBg`, `primaryTeal`, `primaryTealDark`, `accentBlue`, `accentPink`, `textMuted`. Pre-existing consumers imported at `8b04bd8` — `flutter/lib/ui/molecules/metric_card.dart`, `history_tile.dart`, `flutter/lib/ui/atoms/app_input_field.dart`, `flutter/lib/ui/pages/home_page.dart` — were not migrated. `83befe9` (Story 4.1) then added `flutter/lib/ui/pages/summary_screen_page.dart` referencing the still-absent `AppColors.cardBg` / `AppColors.textMuted`. `717ee3c` ("apply code review patches") did not catch it. Fixed 2026-09-02 by re-adding the four constants (two as real colours, two as `surface` / `textSecondary` aliases).
Disposition: **fixed** (this session). Upstream: same gate as F1; a palette/token change must grep every `AppColors.` reference.

**F3 — `AppInputField` was called with a parameter it did not declare.**
Source: `flutter/lib/ui/pages/profile_page.dart:105,119` pass `onChanged:` to `AppInputField`; the widget (`flutter/lib/ui/atoms/app_input_field.dart`, at `8b04bd8`) had no such parameter → compile error, so `ProfilePage`'s dynamic-BMI behaviour never worked. Fixed 2026-09-02 by adding `final ValueChanged<String>? onChanged` and wiring it to the inner `TextField`.
Disposition: **fixed** (this session).

**F4 — The signed FHIR / PDF physician export — a headline capability in the PRD, the README, and Story 4.1's Intent and I/O matrix — is unimplemented, and its test is vacuous.**
Source:
- `spec-4-1` Intent: "…and signed physician FHIR JSON / PDF report export." I/O matrix row "Physician Report Export": "Generates signed FHIR JSON payload & PDF preview toast."
- Implementation: `flutter/lib/ui/pages/summary_screen_page.dart:154-161` — the export button's `onPressed` only calls `ScaffoldMessenger…showSnackBar("Exporting Signed FHIR JSON / PDF Clinical Report...")`. No FHIR or PDF code exists anywhere under `flutter/lib/` (`find flutter/lib -iname "*fhir*"` → empty).
- `flutter/test/core/fhir_report_exporter_test.dart` (116 lines, `6cb8e4b`) defines its own `MockFHIRReportExporter` **inside the test file**, imports nothing from `lib/`, and asserts that a hardcoded literal map equals itself.
- `_bmad-output/implementation-artifacts/tests/test-summary.md`: "Core Signal & FHIR Logic Coverage: **100%** of `ApneaEvaluator`, `BLESensorDriver`, and `MockFHIRReportExporter` APIs." The 100% is of a class that exists only in the test.
- Story 4.1's written **Acceptance Criteria** cover only the score ring and the waveform pan — the export is in the Intent but has no acceptance criterion, so the story could be marked `done` against its own checklist while the Intent contract was unmet.
Disposition: **defer → action item**. This is a spec-vs-implementation gap, not a same-session fix.

**F5 — Test suites were committed detached from the stories, and not covered by any story's verification section.**
Source: `615b495` and `6cb8e4b` carry no story id; no story spec's Verification section mentions `flutter test`. Yet `test-summary.md` presents the suite as complete coverage "for all specs."
Disposition: **fix now** (process). Upstream: tests belong in the story commit and in the story's Verification block.

**F6 — Test files that never executed were counted as passing coverage.**
Source (all fixed 2026-09-02):
- `flutter/test/core/ble_sensor_driver_test.dart:30` used `isGreaterThan(0.0)` — not a `package:matcher` symbol → file did not compile → the whole `flutter test` run aborted.
- `flutter/test/core/apnea_evaluator_test.dart`, `ble_sensor_driver_test.dart`, `flutter/test/ui/login_page_test.dart`, `profile_page_test.dart`, `summary_screen_page_test.dart` imported app code as `../../lib/...` (`avoid_relative_lib_imports`).
- `flutter/test/widget_test.dart` referenced `MyApp`; the root widget was renamed to `MaskerApp` in `bb5df9f` and the default template test was never updated.
- `profile_page_test.dart` and `summary_screen_page_test.dart` asserted against finders that could not match as written (`find.text` colliding with a field hint; a tap on an off-screen button).
Disposition: **fixed** (this session). `flutter test` now runs 14/14.
